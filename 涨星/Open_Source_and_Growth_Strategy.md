### 项目定位建议

不要把 ClawLoops 讲成 “公司内部部署脚手架”，而要讲成 “让 OpenClaw 变成团队可落地、可治理、可自托管的平台层”。

## 1. 一句话价值主张

推荐外部描述：在一台服务器上，把 OpenClaw 变成支持多用户登录、容器级隔离、统一模型接入、默认模型开箱可用、最小审计与用量可见的团队平台。

| 推荐命名                              | 适用场景                                            |
| ------------------------------------- | --------------------------------------------------- |
| OpenClaw for Teams                    | 对外传播最直接，适合作为 README 标题副标题。        |
| Multi-tenant-ready OpenClaw Platform  | 强调后续扩展空间，但不要在 MVP 中夸大已实现多租户。 |
| Self-hosted Team Runtime for OpenClaw | 强调自托管 / 团队协作 / 平台化运行。                |

## 2. README 首屏怎么打

- 第一屏先放一句话价值主张，不要先放大架构图。
- 紧接着放一张总览图或 GIF，展示 “登录 -> 启动 runtime -> 进入工作区” 的闭环。
- 首屏三条卖点建议固定为：多用户登录、每用户独立 runtime、统一模型网关。
- 明确声明 MVP 的边界，避免用户误以为已经有复杂多租户与复杂共享空间。

## 3. 把项目从 “方案” 变成 “5-10 分钟可跑”

| 必须项                             | 目的                             |
| ---------------------------------- | -------------------------------- |
| docker compose up 的最小可运行版本 | 降低试用门槛。                   |
| 单机 demo 模式                     | 让用户先体验闭环，再看复杂配置。 |
| 默认模型后端                       | 避免首次体验就卡在外部 API Key。 |
| 演示账号与体验路径                 | 让读 README 的人知道怎么试。     |
| GIF 或 60 秒视频                   | 快速建立 “真的能跑” 的信心。     |

## 5. 发布节奏建议

| 版本   | 建议边界                                                     |
| ------ | ------------------------------------------------------------ |
| v0.1.0 | Authentik 登录 / 每用户独立 runtime/runtime manager/LiteLLM 网关 / 最小 Web UI/docker compose demo。 |
| v0.2.0 | 共享空间雏形或共享资源占位 / 管理侧用户视图完善 /runtime 状态页增强。 |
| v0.3.0 | API Key 管理增强 / 模型策略增强 / 更清晰的 quota。           |
| v0.4.0 | usage 汇总增强 / 审计日志 / 费用看板雏形。                   |
| v0.5.0 | provisioner 插件化 / 更多后端适配。                          |

每次 release 都应该带着 “用户能感知到的变化” 来发布，而不是只发代码。发布说明要明确新增能力 / 限制 / 迁移方式和截图。

## 6. 对比表怎么写

README 里建议加入 “为什么不是直接用原生 OpenClaw” 的对比表，但要诚实，不夸大。

| 能力         | 原生 OpenClaw | ClawLoops             |
| ------------ | ------------- | -------------------- |
| 多用户登录   | 弱 / 无       | 有                   |
| 运行时隔离   | 偏个人使用    | 每用户独立 runtime   |
| 统一模型接入 | 分散          | LiteLLM 网关统一出口 |
| 管理后台     | 弱 / 无       | 有                   |
| 费用管理     | 弱 / 无       | 路线图中             |
| 企业部署     | 需自行拼装    | 开箱部署目标更明确   |

## 7. 对外传播措辞建议

- We turned OpenClaw into a multi-user self-hosted team platform.
- Run one OpenClaw server for your whole company.
- OpenClaw for Teams: isolated runtimes, SSO, model gateway.
- Self-hosted OpenClaw with per-user runtimes and enterprise controls.

### 措辞提醒

已经将 “严格隔离” 修正为 “容器级隔离” 或 “per-user isolated runtime”，避免对安全边界做过强承诺。

## 8. 社区协作门槛

- 尽早开放 issue 模板 / PR 模板 / 贡献指南。
- 尽早公布 roadmap，让潜在贡献者知道项目是否长期维护。
- 用截图 / 短视频和 demo 降低理解门槛。
- 不要等火了再补文档；基础文档本身就是涨星和留存的一部分。
